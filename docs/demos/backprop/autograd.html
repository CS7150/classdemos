Backprop, step by step: what loss.backward() actually does

Type an expression the way you would in PyTorch. The page runs it the way an autograd engine does, in three phases: build the graph as Python evaluates each operation, run the forward pass in topological order, then run the backward pass in reverse order. At every node, the chain rule multiplies the upstream gradient by the node's local gradient to get the downstream gradient for each input.

Colors. Green numbers are values from the forward pass. Red numbers are
  gradients of the loss, ∂L/∂(·), flowing backward; where a node feeds several others, the small red numbers on its edges are the share each one sends back,
  before they are added up. Violet numbers are local gradients, which a node can work out from its own inputs alone.

 
Where this differs from PyTorch. PyTorch computes each operation the moment Python reaches it, so building the graph and
  the forward pass happen together. They are split here, as in the homework's autograd, so you can see the graph before any number moves.
  PyTorch also keeps .grad only on leaves (call retain_grad() to keep an intermediate one) and stores plain
  Python numbers like 4 inside the operation instead of making nodes for them. Here every node shows its gradient, and
  constants are drawn as dashed boxes that get no gradient.

 
What you can type. + - * / **, parentheses, sin cos exp log tanh sigmoid relu sqrt abs pow square,
  and add sub mul div neg, each as a function (sin(x), torch.pow(x, y)) or a method (x.sin(), x.pow(y)), and several lines of
  assignments; the last one is the loss. Every unassigned name is a leaf tensor with requires_grad=True.
  Keys: → step, ← back, space play.
